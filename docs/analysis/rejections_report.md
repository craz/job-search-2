## 8. Автоотказ: просмотр и отказ почти одновременно

Правило: для отказа берём `last_message_at` (иначе `last_activity_at`), ищем просмотры той же компании в `resume_views` этого резюме, берём ближайший `viewed_at`. Если |Δ| **&lt; 10 секунд** — считаем автоотказом.

**Важно про данные:** HH в истории просмотров отдаёт время с точностью до **минуты** (`…:00`). Отказ же с миллисекундами. Поэтому часть явных автоотказов попадает в корзину «та же минута» (Δ 10–59 с), а не в &lt;10 с. Ниже обе корзины.

## Где данных не хватило

- Реальная дата отклика для `source=chatik` (~90% карты) — нельзя считать скорость отказа по истории.
- Описания вакансий: запрошено 127, получено 55 (Core miss/fail: 72).
- Сопоставление компаний view↔reject — по нормализованному имени, не по HH employer id.
- `resume_views` не гарантирует полную историю просмотров; время просмотра — с точностью до минуты.
- П.7 — эвристики по заголовкам/reason, не замена DevAI + scoring-policy.
- П.8: порог &lt;10 с на минутных `viewed_at` занижает автоотказы; смотреть также Δ&lt;60 с.
- В chatik `negotiation_topics` нет created_at — бэкфилл даты отклика этим списком невозможен.
- Ответы анкеты работодателя по конкретным автоотказам в кеше не привязаны.
