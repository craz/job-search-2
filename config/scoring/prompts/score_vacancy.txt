Правила жёсткого SKIP (decisive_factors):
- FIT.1c_engineering_required — руководство разработкой/внедрением 1С (не интеграция Bitrix↔1С)
- FIT.crm_manager — профессия CRM-manager / ведение базы, не PM
- FIT.commercial_primary — ТОЛЬКО если ОСНОВНАЯ функция должности = sales / BDM / KAM / account / «развитие бизнеса» / план продаж / квота / закрытие сделок (не продуктовая экономика)
- DESIRABILITY.sales_managers_leadership.skip — обязательное управление РОПами / руководителями продаж
- DESIRABILITY.leadgen_partnerships_primary.skip — обязательная самостоятельная лидоген / коммерческое развитие партнёрской сети
- DESIRABILITY.dedicated_crm_analyst.skip — выделенный CRM-аналитик
- DESIRABILITY.infrastructure_primary.skip — инфра/ops/админ IT как основная суть
- FIT.non_it_product_primary — PM / «разработка» физического или иного не-IT продукта как ОСНОВНАЯ суть (бытовая техника, аэроигрили, мебель, станки, стройматериалы, одежда и т.п.)
- DESIRABILITY.international_relocation.skip — работа/релокация за рубеж
- также skip: CIO/CTO/CMO, team lead разработки, SA/BA как основная роль, маркетинг, support-only, junior «начни карьеру PM»

=== FIT.non_it_product_primary: физический продукт vs IT delivery ===

СТАВЬ FIT.non_it_product_primary + verdict skip, когда роль — проектный менеджмент **разработки/вывода физического (или иного не-software) продукта**, а не IT/digital delivery:
- в названии/описании «разработка аэрогрилей / МБТ / мебели / станков» и суть = железо, конструкция, производство, сертификация товара;
- нет IT/software/web/mobile/CRM/ERP delivery как основной работы.

НЕ ставь (это целевые IT-роли, даже в «железной» отрасли):
- PM IT / Delivery / Scrum в компании-производителе (сайт, CRM, ERP, мобильное приложение, интеграции);
- IoT / firmware / embedded / MES / цифровизация производства;
- e-com / marketplace delivery.

Пример SKIP: «Менеджер проектов (Разработка аэрогрилей)».
Если смесь «продукт + IT» и IT не ядро — maybe; если ядро явно не IT — skip.

=== FIT.commercial_primary: sales vs product-economy ===

СТАВЬ FIT.commercial_primary и/или DESIRABILITY.leadgen_partnerships_primary.skip + verdict skip, когда основная обязанность — продажи/лидоген/коммерческое партнёрство:
- Head of Sales, директор по продажам, BDM, KAM с квотой/pipeline, личное привлечение клиентов/селлеров как core duty;
- фандрайзинг / fundraising / привлечение средств / развитие корпоративных партнёрств / поиск компаний-партнёров и переговоры о сотрудничестве (даже в благотворительном фонде / НКО) — это BD/лидоген, НЕ IT-delivery;
- «руководитель по развитию партнёрских инициатив» без IT/software delivery как ядра.

НЕ ставь FIT.commercial_primary (это product-economy / delivery, не sales-профессия):
- CPO / Head of Product / Product Owner / руководитель по продукту
- GMV, CAC, LTV, Take Rate, P&L продукта, юнит-экономика, монетизация платформы, пилотные продажи MVP
- развитие продукта, интеграции, backlog, разработка
- PM/Delivery, который лишь координирует уже существующих подрядчиков/B2B-заказчиков в IT-проекте

Если роль продуктовая, но опыт кандидата слаб для Senior CPO — вердикт maybe / skip по role fit (другие factors), БЕЗ FIT.commercial_primary.
Если неоднозначно (продукт + коммерция) — maybe, без необоснованного hard sales-SKIP.
Если CPO/продукт, но ОСНОВНАЯ обязанность лично привлекать продавцов и клиентов — FIT.commercial_primary допустим.
Проектная лексика (сроки, бюджет, команда) у фандрайзера/BD НЕ превращает роль в apply/maybe: ядро = привлечение партнёров/средств → skip.

НЕ режь EXCLUDE-01/02 за работу с существующими B2B-клиентами, подрядчиками, CRM-процессами как контекст проекта.
PO/Product без delivery → maybe/skip по смыслу роли, не через commercial_primary.

Целевые роли (apply/maybe): Delivery / TPM / PM IT / Scrum (delivery) / release при IT/product/web; интеграции CRM/ERP (Bitrix24↔1С); B2B, e-com/web/mobile delivery.
